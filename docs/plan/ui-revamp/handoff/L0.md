## How to use the contract (what a page lane needs beyond 07)
- **Load order** `theme.css` → page CSS → bundles → `site.js` → page JS. `check_page()` asserts `theme.css` is the first
  stylesheet and that no `data/…` bundle loads after `site.js` (`load_order=False` turns that off if a page must).
- **Nav:** put `<nav class="site-nav" data-page="<id>"></nav>` in the page; `site.js` fills it on load. No JS call needed.
  The page's old header (`.top`, brand, eyebrow) is the lane's to remove or keep below the nav.
- **Footer:** an empty `<footer class="footer-strip"></footer>` gets the default sentence; call `Site.footer(text)` to
  set a page-specific one (for example "numbers read from start_bundle.js"). Keep digits out of it.
- **`Site.tokens()`** returns `{paper, card, inset, ink, "ink-2", "ink-3", faint, line, mustard, "mustard-ink",
  "mustard-tint", brick, "brick-tint", brown, carbon, fontSans, fontMono}` as `#RRGGBB` strings, resolved for the current
  theme, cached per theme (`Site.tokens(true)` re-reads). Hyphenated keys need brackets: `t["ink-3"]`. Read it once at
  start in place of the literal `C = {...}` in `flow.js` / `encounter.js`.
- **`?theme=night`** sets `data-theme="night"` on `<html>` (before the nav is drawn) and nav links carry it along. Pages
  that build their own links to other pages should not need to care. `?theme=paper` clears it.
- **Digits:** the no-digit check treats `<code>`, any element with class `cmd`, `<script>`, `<style>` and comments as not
  page text. Numbered headings like "1 SIMULATE" must not be typed: use a CSS counter or `::before{content:…}`, or bind
  them in JS.
- **Old page re-themed in place** (L6, or as a first step): link `theme.css` *after* the page CSS. Aliases then win and
  the background grid is switched off. Hard-coded colours (`rgba(10,15,20,.94)` sticky headers, `linear-gradient(#111A24,#16222F)`
  rows in `start.css`, `#0E161F` in `jev.css`, the `C = {...}` canvas literals, `index.html`'s `body::after` scanlines) are
  not caught and stay dark: the lane replaces them.
- Classes: one `.btn--primary` per view; `.stamp` text never claims clinical validation; `.drawer` is fixed to the right edge,
  hidden until `.drawer--open`; `.chip` is an outlined tag or toggle, `.cmd` is the black terminal chip.

## Do not recreate
- No page-specific classes in `theme.css`; no `:root` palette in page CSS of rewritten pages.
- No hard-coded nav links in pages: the nav comes only from `Site.pages` in `site.js`.
- No web fonts or CDN links; fonts live in `demo/fonts/`.
- No background grid, gradients, glow or scanlines.
- No stamp or text claiming clinical validation anywhere (the site test greps theme, site.js, skeleton and every site page).

## Open issues and judgement calls
- **Fonts: vendored.** Inter 400/600/700 and Courier Prime 400/700, latin subset woff2 from the Fontsource npm packages
  (packaging of the official OFL releases), about 120 KB in all, `@font-face` with `local()` first and `font-display: swap`.
  Latin covers Finnish letters; other scripts fall back to the stacks in 05-theme.md.
- **Alias values** differ from 05-theme.md's sketch where old pages use the colour as text: `--amber` → `--mustard-ink`
  (not `--mustard`, which fails contrast as text), `--coral` → `--ink-3` (not `--faint`, never text). `--blue` → `--ink-2`,
  `--violet` → `--brown`, `--mint` → `--ink`, `--red` → `--brick`.
- **Night block** also maps the new tokens to dark values, so rewritten pages get the fallback too. It is the old look,
  not a designed dark theme.
- Base element styles are wrapped in `:where()` (zero specificity) so page rules always win; shared classes have normal
  class specificity.
- `.lede` is Inter 20 (05-theme.md gives no size); `.caption` is Courier Prime 13 `--ink-3`.
- Handoff file name: `L0.md` (the brief says `L0-foundation.md`; Tuomas's session asked for `L0.md`).
