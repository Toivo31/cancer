Model card: JEV is a decision model, not a chatbot.

It reads a context, takes a question with a fixed list of allowed answers, and returns one score per answer in a single pass. The answers are what the pathway allows at that node, so it can only propose a step that exists.

Optional, off by default: the backbone's original language head calls read-only tools and writes a short evidence summaryappended to the context
Contextrecord, symptoms, notes, tool results→ Frozen backbone + trained adapters→ context vector
Each answer, with its questionencoded on its own→ same encoder→ one vector per answer
Scoring head: the answers attend to each otherscore = direct match with the context + a correction from the whole answer set→ one score per answersoftmax over the offered answers→ a person accepts or overrides

How it works, step by step

    Live calls need an endpoint and start only when you press a button.

    Opened from the file, the page shows recordings only and makes no network call. Choose an endpoint in the bar above the examples, or add ?api=hosted, ?api=same or ?api=<url> to the address. To serve this folder and the decision proxy on one origin:

    python demo/serve_jev.py

    Model code: decision_api/runtime/decision_model/ (on main). The adapter the simulator calls: jev/birch.py. Page data: demo/data/jev_bundle.js, built by demo/export_jev.py.

    Synthetic patients only · not clinically reviewed · every answer is a proposal for a person to review
